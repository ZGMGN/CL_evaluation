# 训练前后漂移 / 任务冲突分析

> 想要一份"每个指标是怎么算的、目的是什么、怎么比较"的完整清单，见 [`METRICS.md`](METRICS.md)。

四个脚本，都读 `datas_clean/` 和 `train1_continual_lora/`（按任务前缀命名的 adapter），
结果默认写到 `analysis_results/<脚本名>/`，每个目录里都有 `summary.json` + csv + 热力图。

```bash
# 1) LoRA 参数漂移（纯 CPU，几秒钟）
python3 analysis/lora_cosine.py --stages AGNEWS AGNEWS+QQP AGNEWS+QQP+SST2 AGNEWS+QQP+SST2+TLDR

# 2) 任务梯度冲突（GPU，每个阶段一次模型加载）
python3 analysis/grad_cosine.py --stages AGNEWS AGNEWS+QQP --tasks AGNEWS QQP SST2 TLDR

# 3) 表示漂移（GPU，前后各一次模型加载）
python3 analysis/representation_drift.py --before base --after AGNEWS --tasks AGNEWS SST2
python3 analysis/representation_drift.py --before AGNEWS --after AGNEWS+QQP --tasks AGNEWS QQP

# 4) 功能漂移（GPU，前后各一次模型加载）
python3 analysis/functional_drift.py --before base --after AGNEWS --tasks AGNEWS SST2 TLDR
```

**所有指标统一在 val2 上算**（`--split` 默认就是 `val2`）。为什么用 val2：`train1.py` 是
拿 `train.jsonl` 训练、`val1.jsonl` 选 checkpoint 的，所以 val2 是**完全没参与训练和模型
选择**的干净留出集；`prepare_activation.py` 的相似度分析用的也是 val2，结果可以互相对照。
（`lora_cosine.py` 只读权重、不碰数据，所以没有这个选项。）

其它公共参数：`--tasks`（分析哪几个任务）、`--max-samples`、`--batch-size`（显存不够会自动
折半重试）、`--max-length`、`--out-dir`。val2 每个任务有 500 条，够用。

---

## 四个脚本的因果链

它们不是四个孤立的指标，而是同一件事的四个层次：

```
Gradient Cosine        理论上"应该"往哪个方向更新            → analysis/grad_cosine.py
        ↓
Actual ΔW Cosine       训练实际"走"出来的方向（δW 两两余弦）   → analysis/lora_cosine.py
        ↓
Representation Drift   内部表示因此改变了多少                  → analysis/representation_drift.py
        ↓
Functional Drift       最终行为（输出分布）因此改变了多少       → analysis/functional_drift.py
```

前两个可以直接对照：**同一对任务，梯度余弦和 δW 余弦差多少**，就说明"想更新的方向"和
"实际更新出来的方向"差多少。后两个是这个更新在表示层和行为层留下的后果。

## 1. LoRA 参数漂移（`lora_cosine.py`）

**量什么**：训练把权重改了多少、往哪个方向改。

LoRA 的等效权重增量是 `ΔW = B @ A * (alpha / r)`。这里**不能**直接把 lora_A / lora_B
拼成一个向量算余弦 —— A、B 有缩放不变性（A→sA、B→B/s 给出同一个 ΔW），拼起来比会把
这种尺度差异当成"方向差异"。必须先还原成 ΔW。

输出三张表：

- `stage_cosine.csv`：任意两个阶段的**累计** ΔW 之间的余弦。对角线是 1；离对角线越远越小，
  说明后面的训练把方向拐得越远。
- `stage_drift.csv`：相邻阶段（下面细说）。
- `layer_cosine.csv` / `layer_update_cosine.csv`：上面两个量的逐层版本，
  用来看漂移和抵消集中在哪几层。

### 重点看这一个：`cos(δW_k, ΔW_{k-1})`

记 `ΔW_k` 是训到第 k 个任务为止的**累计**增量，那么第 k 个任务自己新产生的那部分是

```
δW_k = ΔW_k − ΔW_{k-1}
```

脚本算的是 `cos(δW_k, ΔW_{k-1})` —— **本任务新产生的更新，和"过去所有任务积累下来的方向"
之间的关系**：

| 值 | 含义 |
|---|---|
| > 0 | 新更新和旧方向一致：这个任务在**强化**已学到的方向 |
| ≈ 0 | 正交：这个任务在开辟新方向，基本不碰旧的 |
| < 0 | 新更新和旧方向相反：这个任务在**抵消**旧方向（持续学习里最该警惕的信号） |

它比 `cos(ΔW_k, ΔW_{k-1})` 更有解释力：后者是"两个累计量之间的夹角"，会被累计量本身
的惯性稀释 —— 即使新任务在大量抵消旧方向，只要 `ΔW_k` 和 `ΔW_{k-1}` 都很大，
这个夹角仍然可能看着很"稳"。`δW_k` 才是这个任务真正做的那件事。

同时给出的两个辅助量：

- `cos(δW_k, ΔW_k)`（`cos_update_to_curr`）：和"更新完之后的方向"比，≈1 说明这一段基本
  只是把旧方向延长；
- `||δW_k|| / ||ΔW_{k-1}||`（`norm_update_over_prev`）：这一段改动的相对幅度；
- `cancel_ratio = max(0, 1 - cos_update_to_prev)`：粗略的"抵消比例"。

三个量都从同一组标量推出来，不需要真的构造 `δW` 向量：
`⟨δW_k, ΔW_{k-1}⟩ = ⟨ΔW_k,ΔW_{k-1}⟩ − ‖ΔW_{k-1}‖²`、
`‖δW_k‖² = ‖ΔW_k‖² + ‖ΔW_{k-1}‖² − 2⟨ΔW_k,ΔW_{k-1}⟩`。

### 和 Gradient Cosine 配对：`cos(δW_i, δW_j)`

把每个任务**自己造成的**那一份更新拿出来互相比较：

```
δW_i = ΔW_i − ΔW_{i-1}        ← 第 i 个任务"这一件事"造成的 LoRA 更新
```

（`base` 视为零向量，所以第一个阶段的 `δW_1` 就等于它的累计 `ΔW_1`。）

得到的是"任务 × 任务"的矩阵，含义和 Gradient Cosine 完全对应：

| | 回答的问题 | 量的是 |
|---|---|---|
| Gradient Cosine | 理论上应该往哪走？ | 梯度方向（当前权重处的局部方向） |
| **δW Cosine** | 实际走出来了哪？ | 权重真正移动的方向 |

两边的符号/大小对不上的地方，就是"想更新成什么样"和"实际更新成什么样"的差距（比如
梯度看着正交，实际却因为优化动态而互相抵消）。

输出：`task_delta_cosine.csv`（任务 × 任务）、`task_delta_cosine.png`，
以及逐层的 `layer_task_delta_cosine.csv/.png`（行=任务对，列=层，看哪几层在打架）。
对角线上是 1，矩阵对称。

同样不用构造 `δW`（它有 13 亿个数），四个累计内积一组合就出来：

```
⟨δW_i, δW_j⟩ = ⟨ΔW_i,ΔW_j⟩ − ⟨ΔW_i,ΔW_{j-1}⟩ − ⟨ΔW_{i-1},ΔW_j⟩ + ⟨ΔW_{i-1},ΔW_{j-1}⟩
```

注意它是**累计**增量：`A+B/` 里的权重是"相对基座、训过 A 和 B 之后"的总增量，
不是 B 单独的增量。所以脚本用"相邻两个累计量之差"来近似"本任务的新增更新"。

## 2. 任务梯度冲突（`grad_cosine.py`）

**量什么**：不同任务在这一步想要的更新方向是否冲突。

做法：在某个训练阶段上，用每个任务的一小批样本分别做一次前向+反向，取 LoRA 参数
的梯度向量 `g_i`，然后算 `cos(g_i, g_j)`。含义：

| cos | 含义 |
|---|---|
| 明显 > 0 | 两个任务方向一致，一起训会互相帮助 |
| ≈ 0 | 基本正交，互不干扰 |
| < 0 | 冲突，一起训会互相拖（PCGrad 那篇的动机） |

三个注意点：

1. **梯度是局部量**。同一个任务对，在不同阶段（base / A / A+B）算出来的余弦可能差很多，
   所以用 `--stages` 一次跑多个阶段看演化，比只看一个点有信息量。
1.5 **损失口径与归一化**。每个 batch 直接用模型自己的 `out.loss`：labels 里的 `-100`
   已被排除，所以它本身就是"该 batch 内有效 token 的平均"（transformers 的
   `fixed_cross_entropy` 在 `num_items_in_batch=None` 时用 `reduction="mean"`）。
   各 batch 的梯度累加后除以 **batch 个数**。别再多除一次 batch_size —— 那既不是
   "样本平均梯度"，又会让样本数不足的尾批被额外放大（实测 `||g||` 差 2.6 倍）。

   两种口径用 `--loss-weight` 选：`token`（默认）和 `train1.py` 的训练目标一致，
   batch 内所有有效 token 等权、回答长的样本会被放大；`sample` 是每个样本先按自己的
   有效 token 平均、再对样本平均，每个样本等权（MEDDIA 的回答长度 2~472 token 不等，
   两种口径差别很大）。

   实测（假数据、回答长度 1~8 句不等）：`sample` 口径换 batch size 梯度方向不变
   （cos = 0.999998），`token` 口径会漂（batch 1 vs 8 时 cos = 0.9923）。另外余弦对
   整体正数缩放不敏感，所以这两个口径主要影响 `||g||` 的可解释性和尾批权重，
   对余弦矩阵本身影响很小（实测 ~1e-4 量级）。
2. **样本量要够**。默认每个任务 16 条 × 3 轮，样本太少时余弦的方差很大
   （实测同一阶段两轮的梯度范数能差好几倍）。结果里的 `cosine_std` 就是轮间标准差。
   实测在 `AGNEWS` 这个已经训过的任务上，梯度范数会在两轮之间差到两个数量级
   （大部分样本 loss 已经接近 0，少数错样本主导了范数）。正式跑建议
   `--max-samples 32 --repeats 3` 起步，并且只看 `cosine_std` 小的那些格子。
3. 只有 LoRA 参数有梯度（基座冻结），所以这个余弦是"LoRA 子空间里的冲突"。
   `--stages base` 用的是随机初始化的 LoRA（此时 lora_B=0，对 A 的梯度恒为 0，
   脚本手动加了个小扰动），只能当"初始冲突"的参考，不要和训练后的数直接比。

   为什么 base 非得挂一个随机 LoRA：LoRA 训练里基座参数是冻结的，
   `requires_grad` 全是 False，backward 之后一个梯度都拿不到，根本上不了这张表；
   而其它阶段都是 LoRA 形态，为了同构只能临时挂一个。随机种子已固定（`--seed`），
   同一个 seed 下结果可复现。**想要真正的"训练前"参考，用序列里的第一个 adapter
   （比如 `--stages AGNEWS AGNEWS+QQP`），而不是 base。**

## 3. 表示漂移（`representation_drift.py`）

**量什么**：同一批样本，训练前后模型的中间层表示变了多少。

同一批 val 样本分别过"训练前"和"训练后"的模型，取若干层 hidden state 做
masked mean pooling（和 `prepare_activation.py` 一致），然后：

| 指标 | 含义 | 怎么读 |
|---|---|---|
| 配对余弦 | 同一条样本前后表示的方向变化 | 1 = 没动；掉到 0.8 说明转了不少 |
| `1 - 余弦` | 余弦距离 | 和上面等价，越大漂移越大 |
| 相对 L2 | `‖h_after − h_before‖ / ‖h_before‖` | 幅度变了多少（余弦看不出的整体缩放） |
| 线性 CKA | 两组表示的整体几何相似度 | 不要求配对，衡量"表示空间有没有被重排" |
| 线性映射 R² | 漂移能不能被一个线性映射解释 | 半拟半测的 R²，1 = 前后表示由一个线性映射连着 |

### 余弦和 CKA 不是一回事，别混着说

它们回答的是两个不同的问题：

| 指标 | 回答的问题 |
|---|---|
| 配对余弦 | **这一条样本**的表示变了没有？ |
| CKA | **整个表示空间的几何结构**变了没有？ |

所以两个数要合起来读。脚本会自动给一个判定（阈值 `--threshold`，默认 0.9）：

| 余弦 | CKA | 线性 R² | 判定 | 含义 |
|---|---|---|---|---|
| 高 | 高 | — | 基本没动 | 没怎么变 |
| 低 | **高** | — | 整体保距变换（旋转/缩放） | 单条表示都转了，但内部几何结构还在 |
| 低 | 低 | 高 | 线性但非保距 | 能被线性映射解释，但把几何拉伸了 |
| 低 | 低 | 低 | 非线性重排（**真漂移**） | 结构本身被重写 |
| 高 | 低 | — | 幅度重排 | 方向没变，相对尺度/夹角变了 |

这几种情形用合成数据验证过（n=200, d=64，`b` 由 `a` 按已知方式变换而来）：

```
情形              余弦      CKA     线性R²    判定
恒等            1.0000   1.0000   1.0000   基本没动
整体旋转         -0.0734   1.0000   1.0000   整体保距变换（旋转/缩放，几何保持）
线性缩放 0.5*R   -0.0457   1.0000   1.0000   整体保距变换（旋转/缩放，几何保持）
一般线性映射      0.0281   0.7407   1.0000   线性但非保距（一般线性映射）
旋转+10% 噪声    -0.0550   0.9925   0.9726   整体保距变换（旋转/缩放，几何保持）
非线性（平方）    -0.0107   0.2559  -1.6659   非线性重排（真漂移）
完全无关（随机）  -0.0044   0.2390  -1.7848   非线性重排（真漂移）
只改一半维度      0.5036   0.6376  -0.3628   非线性重排（真漂移）
```

注意"整体旋转"那一行：**余弦是 -0.07（看着像完全变了），但 CKA 精确等于 1** —— 这就是
你说的那个情形，单看余弦会得出完全错误的结论。反过来，只看 CKA 又会漏掉"整体旋转"
这类变化。所以论文里要写清楚这两个指标各自回答什么问题、以及为什么要一起报。

真模型上的例子（base → AGNEWS adapter，val2 上每任务 200 条）：

```
任务      层     余弦      CKA    线性R²   判定
AGNEWS  L16   0.9631   0.8850   0.5567   方向没变但尺度/几何变了（幅度重排）
SST2    L16   0.9861   0.9994   0.7923   基本没动
AGNEWS  L24   0.9708   0.9532   0.4496   基本没动
SST2    L24   0.9806   0.9914   0.5773   基本没动
AGNEWS  L32   0.8672   0.9497   0.4786   整体保距变换（旋转/缩放，几何保持）
SST2    L32   0.8556   0.9900   0.5419   整体保距变换（旋转/缩放，几何保持）
```

可以看到两点：训练在 AGNEWS 上对"AGNEWS 题目的表示"改动更大（同层 CKA 比 SST2 低），
而 R² 只有 0.45~0.79 —— 说明这个漂移**不是**一个干净的整体线性变换，只能部分用线性
映射解释。要判断"是不是整体旋转"，R² 这一列比 CKA 更有决定性。

另外两个实现细节：

- CKA 用的是线性 CKA，对正交变换和各向同性缩放不变（这就是"旋转后 CKA 仍然 = 1"的原因）；
- 线性 R² 是**半拟半测**（一半样本拟合线性映射，另一半算 R²），否则 n < d 时最小二乘
  一定能在训练集上完美拟合，R² 会永远等于 1。样本少于 32 条时不给 R²（返回 nan）。

显存：一次只加载一个模型，另一个的中间结果缓存在 `repr_*.pt`，
加 `--reuse` 可以跳过已经算过的那一遍。

## 4. 功能漂移（`functional_drift.py`）

**量什么**：模型"输出"这个层面变了多少 —— 也就是你公式里的
`D_func = KL(P_M1(y|x) ‖ P_M2(y|x))`。

在同一批样本、同一个位置上比较下一个 token 的分布：

- `symmetric_kl` = `KL(before‖after) + KL(after‖before)`（默认主指标）
- `js_divergence` = Jensen-Shannon，有界（0~ln2），跨任务可比性更好
- `top1_agreement`：前后 top-1 token 一致的比例
- `entropy_before/after`：分布熵。**塌缩类失效会在这里露馅** ——
  比如模型学会无脑输出 `0` 时，熵会明显下降
- `prob_before/after` + `rank`：金标准首 token 的概率和排名变化

**位置怎么取**：默认只看回答的第一个 token（分类任务里就是要吐标签的那个决策点），
`--positions K` 可以多看前 K 个（K>1 会成倍增加内存，因为每条样本要存 K 个 128k 维分布，
脚本启动时会预估并打印占用）。

## 四个指标怎么配合看

举个例子：如果某个阶段出现了"格式塌缩"（模型对摘要题开始吐 `0`），四个脚本会给出
互相印证的证据链：

1. **功能漂移**：该任务的对称 KL 很大，同时 `entropy_after` 骤降、`top1_agreement` 低 →
   输出分布被换掉了；
2. **表示漂移**：深层（L24/L32）的配对余弦掉得比浅层多 → 表示确实被推走了；
3. **LoRA 漂移**：`cos(本阶段新增, 上一阶段)` 为负 → 这一阶段是在反向改写；
4. **梯度冲突**：那个任务与其它任务的梯度余弦接近 0 或为负 → 方向上本来就互相拉扯。

单看任何一个都可能有别的解释，四个一起就能把"是能力丢了、还是只是换了输出格式"
区分开。
